# 开发入口运行模式选择设计

## 目标

在 Story 从“已评审”进入“开发中”前，让操作者为**该 Issue**选择一次运行模式：`semi-auto` 或 `full-auto`。选择写入该 Issue 的运行 state，之后恢复会话、重新读取 Issue 或全局配置改动都不改变该选择。

`full-auto` 的目的不是跳过交付门禁，而是在明确授权范围内连续完成开发、验证和测试环境构建；遇到必须由人决定、授权或承担风险的事项时停止，并给出可执行的缺口说明。

## 入口与状态

1. Leader 在“已评审 → 开发中”前读取 Issue、配置和已有 state。
2. 若该 Issue 尚无 `runModeSelectedAt`，询问一次：
   - **半自动**：沿用每个节点的预览—确认—写回。
   - **自动**：在本设计定义的授权范围内连续推进。
3. 将 `runMode`、`runModeSelectedAt`、`runModeSelectedBy` 写入 state；状态标签与 Issue 正文不因选择而改变。
4. 已选择的 Issue 恢复时不重复询问。配置中的 `run_mode` 仅作为旧 Issue 无状态时的默认值，不覆盖明确选择。

## 自动模式的允许范围

当护栏通过且不存在阻断项，Leader 依次执行并在每步完成后回读证据：

1. 生成或更新技术方案、测试计划及可复用测试资产。
2. 实施代码，运行本地完整业务闭环自测。
3. 提交并推送需求分支，创建或更新 Merge Request。
4. 完成允许自动执行的评审、合并至已配置的测试分支，并触发**测试环境**构建。
5. 执行测试环境接口测试与 E2E，回读 Apifox 报告和环境事实。
6. 写回 GitLab 状态评论、证据评论、Milestone 同步，并继续至下一个非硬门禁节点。

自动模式仍须逐步记录 `nodeProgress`、`writebackAudit`、原始测试证据与 GitLab 回读结果。任何写回失败只重试首个未完成阶段，禁止重复发评论。

## 三层异常处置

### 自动恢复

可安全重试且不改变业务语义的失败，例如网络瞬断、临时测试环境不可用、Git fetch 过期。每项最多重试一次，并记录重试结果；仍失败转人工决策。

### 自动修复并留痕

仅限不改变已评审需求边界的工作：补齐可由现有事实生成的文档或测试资产、测试数据整理、实现细节修正、可验证证据回读。修复后必须重新运行受影响验证。

### 必须暂停

以下情况不得由自动模式继续：

- 本地或测试环境测试重试后仍失败；
- Git 内容冲突或需要选择业务语义的合并结果；
- 需要产品确认、负责人确认、日期承诺或业务结论的门禁证据；
- 接口契约、权限、数据迁移、验收标准、页面路由、测试范围或排期发生实质变化；
- 登录、权限审批、受保护分支权限或外部系统授权不足；
- 待发布、生产部署、生产验收、关闭 Issue 等 hard_gate。

暂停信息必须包含：停止步骤、已验证事实、失败/缺口原文、可安全重试次数、需要谁提供什么输入，以及恢复命令或下一步。

## 变更闭环

自动模式发现实质变更时，先生成 `change-impact` 预览并暂停，等待确认。确认后才更新 proposal、design、test-plan、Apifox 资产、代码、排期等受影响产物；测试计划变化必须提升版本，旧环境的 TestRun 与资产审计自动失效并重测。完成后用 `change-close` 回读闭环，才允许继续正向流转。

非实质实现调整可自动记录在技术方案和测试报告中，但也必须重跑受影响检查并保留证据。

## 边界与安全

- `full-auto` 不改变 G1–G16、门禁二值、Issue 评论不可变及最终回读要求。
- 自动权限仅覆盖需求分支提交/推送、已配置测试分支合并和测试环境构建；生产环境永不纳入自动范围。
- Jenkins 仅在配置明确声明允许自动触发、参数可从配置和已回读事实唯一推导时自动执行；否则暂停要求确认参数。
- 不自动绕过登录、授权、审批、受保护分支或任何外部系统权限。

## 验收与测试

1. 新 Issue 在开发入口只询问一次；选择后恢复会话仍使用相同模式。
2. 半自动每个非硬门禁仍要求确认。
3. 自动模式在开发、开发中自测、测试中验证通过后连续推进并保存全部证据。
4. 每一种必须暂停的条件都输出结构化暂停原因，且不会写入后续状态。
5. 自动重试最多一次；第二次失败必须暂停。
6. 生产发布、验收与关闭在自动模式下仍要求人工确认。
7. 原有 `run_mode` 配置与旧 state 保持兼容，不会意外把已运行的 Issue 切换为自动。
