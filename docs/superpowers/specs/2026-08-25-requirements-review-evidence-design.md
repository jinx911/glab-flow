# 需求评审输入取证设计

## 目标

阻止需求评审在遗漏 Issue 图片信息、猜测前端页面地址或存在未决需求决策时通过。

## 方案

引擎为 Story `待评审 → 已评审` 增加 `reviewEvidence` 硬门禁。Leader 读取 Issue 正文和评论，逐张下载图片做 OCR 与视觉核查；对前端信号做路由、菜单权限、组件和分流代码探索；以一次性 grilling 决策账本覆盖目标与范围、角色与权限、业务规则与边界、数据与兼容、验收与多环境验证。

图片必须逐一匹配来源。OCR 已识别时要有文本；无文本图片保留视觉摘要；不可识别直接阻断并形成澄清问题。前端需求必须列明“用户位置、实际路径、路由文件、组件文件、分流条件”；找不到或候选不唯一时阻断并一次性向产品提问。grilling 的未决项也阻断通过，条件默认裁定则可作为已决记录。

引擎不下载图片、不访问代码库、不写 GitLab；它只校验 Leader 回传的结构化证据，并在通过的状态评论内渲染不含 OCR 原文的简要回执。
